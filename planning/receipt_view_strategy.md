# Strategy: Receipt View & "Proof of Payment" Integration

## Vision
In an insurance brokerage, a **Receipt** is more than just a file; it is a financial record of a transaction. The vision is to provide a "Hybrid Receipt View" that serves two purposes:
1. **Financial Integrity**: An internal HealthWatch receipt that proves the system has acknowledged the payment and allocated it to the correct invoices.
2. **Physical Evidence**: Seamless access to the "External Document" (bank slip, M-Pesa screenshot, or insurer-issued receipt) which serves as the ultimate source of truth.

---

## Step 1: Define the "Hybrid" Receipt Model
- **Concept**: Every `Receipt` in the system can have one or more linked `Documents` (entity_type='Receipt').
- **Requirement**: When viewing a Receipt, the system must check for these attachments.

## Step 2: Implement `ReceiptTemplate` (Internal Document)
- **Task**: Create `frontend/src/components/Documents/templates/ReceiptTemplate.tsx` using `BaseDocument`.
- **Content**:
    - Header: HealthWatch Letterhead.
    - Body: "Received from [Client Name] the sum of [Amount]...".
    - Table: Breakdown of which Invoices/Policies this receipt was allocated to.
    - Footer: "This is a system-generated receipt".
- **Verifiable Outcome**: A professional-looking PDF-style receipt generated by the system.

## Step 3: Enhance `UniversalDocumentViewer` for Receipts
- **Task**: Update `UniversalDocumentViewer.tsx` to handle the `receipt` type.
- **New Feature: "Proof Side-Panel"**:
    - If a Receipt has a linked external document, show a toggle or a split view.
    - Left side (or primary): The System-Generated Receipt.
    - Right side (or attachment tab): The External Document (Image/PDF scan).
- **Verifiable Outcome**: Users can see "Our Receipt" and "Their Proof" in the same modal.

## Step 4: Add "Upload Proof" to `AddReceiptForm`
- **Task**: Modify `frontend/src/components/Financials/AddReceiptForm.tsx` to include a file upload field.
- **Action**: When a receipt is created, immediately upload the scan/screenshot and link it to the newly created Receipt ID.
- **Verifiable Outcome**: The workflow becomes: Log Payment -> Attach Scan -> Auto-Allocate.

## Step 5: Document Logic for "External Only" Receipts
- **Vision**: If the user ONLY wants to see the scan (common for legacy data), provide a "View Original" button in the Receipt Viewer that opens the external file in a full-screen lightbox or new tab, bypassing the `BaseDocument` wrapper.

---

## Summary of Why this is Necessary
1. **Auditability**: Auditors need to see the bank slip to verify the system's ledger.
2. **Client Professionalism**: Clients expect an official HealthWatch receipt, even if they sent a screenshot of an M-Pesa message.
3. **Internal Reconciliation**: Staff need to see which Invoices were paid by a specific bank slip without digging through paper files.
